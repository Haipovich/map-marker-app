# Map Markers — карта с маркерами и локальной базой данных

React Native + Expo (Expo Router, TypeScript). Долгое нажатие на карте добавляет маркер, нажатие на маркер открывает экран деталей, где можно прикреплять и удалять изображения. Все данные хранятся в локальной базе SQLite (`expo-sqlite`) и сохраняются между запусками приложения.

## Установка и запуск

```bash
npm install
npx expo install expo-sqlite expo-file-system react-native-maps expo-image-picker
npx expo start
```

Отсканируйте QR-код приложением **Expo Go** (iOS/Android). Ключи Google API не нужны.

> Карта работает только на телефоне/эмуляторе. В браузере показывается заглушка — `react-native-maps` не поддерживает web.

Проверки кода:

```bash
npx tsc --noEmit
npx expo lint
```

## Схема базы данных

Файл базы: `markers.db`.

```sql
CREATE TABLE markers (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  latitude REAL NOT NULL,
  longitude REAL NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE marker_images (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  marker_id INTEGER NOT NULL,
  uri TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (marker_id) REFERENCES markers (id) ON DELETE CASCADE
);

CREATE INDEX idx_marker_images_marker_id ON marker_images (marker_id);
```

Связь «один ко многим»: у маркера может быть много изображений, изображение принадлежит ровно одному маркеру. При удалении маркера его изображения удаляются каскадно.

Дополнительно к схеме из задания создан индекс по `marker_id` внешнего ключа: он ускоряет выборку изображений маркера и подсчёт их количества.

`created_at` хранится в UTC в формате `YYYY-MM-DD HH:MM:SS`; в интерфейсе преобразуется в локальное время (`utils/format.ts`).

### Версии базы и миграции

Версия схемы хранится в `PRAGMA user_version`. При запуске `runMigrations` сравнивает её с последней версией в `database/migrations/index.ts` и применяет недостающие миграции по порядку, каждую в отдельной транзакции вместе с обновлением `user_version`. Если миграция падает, транзакция откатывается, версия не меняется, а ошибка поднимается как `MIGRATION_FAILED`. Если версия базы новее версии приложения, запуск прерывается с той же ошибкой.

Чтобы изменить схему, нужно добавить файл `002_*.ts` с новым объектом `Migration` и дописать его в `migrations/index.ts`.

## Архитектура

- **`database/operations.ts`** — единственное место, где написан SQL. Не знает про React.
- **`database/schema.ts`** — жизненный цикл соединения: открытие, `PRAGMA foreign_keys = ON`, миграции, закрытие, сброс.
- **`contexts/DatabaseContext.tsx`** — владеет соединением и предоставляет компонентам операции из задания (`addMarker`, `deleteMarker`, `getMarkers`, `addImage`, `deleteImage`, `getMarkerImages`) плюс `isLoading` и `error`. Дополнительно: `getMarker`, `addImages` (пакетное добавление в одной транзакции), `retry`, `reset`.
- **Компоненты и экраны** обращаются к базе только через `useDatabase()`.

Операции в контексте выполняются последовательно через очередь промисов: `withTransactionAsync` в `expo-sqlite` не изолирует параллельные запросы на одном соединении, и без очереди чужой запрос мог бы попасть внутрь транзакции.

## Обработка ошибок

Все ошибки приводятся к классу `DatabaseError` с кодом:

| Код | Когда возникает |
|---|---|
| `INIT_FAILED` | не удалось открыть базу или включить внешние ключи |
| `MIGRATION_FAILED` | ошибка миграции или версия базы новее приложения |
| `CONNECTION_LOST` | соединение закрыто, база заблокирована, ошибка ввода-вывода |
| `CONSTRAINT_VIOLATION` | нарушены ограничения: внешний ключ, некорректные координаты, пустой URI |
| `TRANSACTION_FAILED` | не удалась операция, затрагивающая несколько записей (откат) |
| `QUERY_FAILED` | любой другой сбой запроса |
| `NOT_FOUND` | удаляемая запись не существует |

Подход по уровням:

1. **Слой данных** (`operations.ts`). Каждая операция проходит через общую обёртку: логирует результат и превращает любую ошибку SQLite в `DatabaseError` (`toDatabaseError` распознаёт ограничения и потерю соединения по тексту ошибки). Входные данные проверяются до запроса. Удаление маркера и пакетное добавление изображений выполняются в транзакции с автоматическим откатом.
2. **Контекст.** Ошибки инициализации попадают в `error`. Если во время операции соединение потеряно, контекст тоже ставит `error`, и интерфейс переключается на экран восстановления. Остальные ошибки пробрасываются вызывающему коду.
3. **Интерфейс.** `DatabaseGate` показывает индикатор загрузки, а при ошибке — понятное сообщение и кнопки «Повторить» (переподключение) и «Сбросить базу данных» (удаление файла и создание заново, с подтверждением). Экраны показывают `Alert` с текстом из `getUserMessage`; список маркеров на карте при сбое чтения показывает баннер с повтором; экран деталей различает состояния «загрузка», «не найден» и «ошибка».

Освобождение ресурсов: при размонтировании провайдера соединение закрывается. Если инициализация завершилась уже после размонтирования, только что открытое соединение закрывается сразу.

Логирование: `logDb` и `logDbError` пишут в консоль только при `__DEV__` — открытие базы, версия, применённые миграции, каждая операция и каждая ошибка.

## Хранение изображений

`expo-image-picker` возвращает временные файлы из кэша, которые система может удалить. Поэтому при добавлении каждое изображение копируется в постоянную папку приложения (`Paths.document/marker-images`, модуль `utils/image-storage.ts`), а в таблицу `marker_images.uri` записывается путь к копии.

Порядок операций выбран так, чтобы не оставлять «висячих» записей: при добавлении файл копируется до записи в базу (при ошибке базы копии удаляются), при удалении запись удаляется из базы до удаления файла.

## Дополнительно реализовано

- Система версионирования схемы и миграции (`PRAGMA user_version`)
- Восстановление после ошибок: повторное подключение и сброс базы данных
- Постоянное хранение изображений в файловой системе приложения
- Пакетное добавление нескольких изображений одной транзакцией
- Подсчёт изображений каждого маркера одним запросом (`LEFT JOIN` + `COUNT`)
- Последовательная очередь операций с базой
- Логирование операций в режиме разработки
- Предпросмотр изображения на весь экран, лента маркеров, подтверждение перед удалением
- Заглушка для web-версии

## ORM

ORM не используется. Схема состоит из двух таблиц и небольшого набора запросов, поэтому прямой SQL через `expo-sqlite` проще, прозрачнее и не добавляет зависимостей. Типизация обеспечивается интерфейсами строк (`MarkerRow`, `MarkerImageRow`) и мапперами в доменные типы (`Marker`, `MarkerImage`). При росте схемы `operations.ts` можно заменить реализацией на Drizzle без изменений в контексте и компонентах.

## Известные ограничения

- Путь к изображению хранится в виде полного URI. На iOS путь к папке приложения может измениться после переустановки или обновления, и тогда изображения придётся добавить заново.
- Названия маркеров автоматические («Маркер N», где N — `id`), редактирования нет.
- В браузере карта и база недоступны.
